# Security Policy

## Supported Versions

Security fixes are provided on a best-effort basis for the latest version on the default branch.

## Reporting A Vulnerability

Please do not open a public issue for security problems.

Instead, report vulnerabilities privately to:
- `rajeevchand@gmail.com`

Include:
- a short description of the issue
- affected files or endpoints
- reproduction steps
- any proof-of-concept or screenshots that help explain the risk

If the report is valid, the goal is to acknowledge it promptly and coordinate a fix before public disclosure.

## Scope

Examples of reportable issues:
- authentication or authorization flaws
- secret exposure
- unsafe defaults that could expose private data
- remote code execution or command injection
- workflow paths that bypass intended safety boundaries

Non-security product bugs should go through normal issues or discussions.
